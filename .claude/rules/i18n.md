# i18n — reglas

Ver `openspec/specs/i18n.md` para el contrato completo.

- Catálogo `es`/`en` propio de esta app (mismo alcance que `TekoApp-Web/messages/{es,en}.json`,
  paquete Flutter a decidir — `flutter_localizations` + `intl` es el camino estándar, confirmar en
  la fase correspondiente).
- Español es el default (igual que `TekoApp-Web`) — negociación por preferencia del dispositivo,
  con selector explícito en la navegación (ver `openspec/changes/0006-i18n-and-polish.md`, no
  alcanza con negociación automática por sistema operativo).
- El backend traduce sus propios mensajes de error/validación vía `nestjs-i18n`
  (header `x-lang`/`Accept-Language`) — mobile debe mandar ese header consistente con el idioma
  activo en la UI, para que los mensajes de error del servidor también lleguen en el idioma
  correcto.
- **Traducir sobre la marcha, no al final**: cada fase (`openspec/changes/000N-*.md`) que agregue
  texto visible nuevo lo traduce en el momento, no se acumula deuda de traducción para la Fase
  0006 — esa fase es para auditar lo que se haya colado, no para traducir todo de cero.
- Cero strings hardcodeados en widgets — todo texto visible sale del catálogo de traducciones,
  igual que la regla equivalente en `TekoApp-Web`.
