# Spec: Internacionalización (es/en)

## Contexto heredado

- Backend: `nestjs-i18n`, negocia idioma por header `x-lang` (override explícito) o
  `Accept-Language` estándar, fallback a español. Traduce mensajes de excepción/validación —
  nunca la documentación de Swagger (esa queda en español, es para developers).
- `TekoApp-Web`: `next-intl`, negocia por cookie de preferencia (la que setea el selector de
  idioma) > `Accept-Language` del navegador > español por default. Traducción completa es/en de
  toda la UI + toda la API (namespaces por dominio en `messages/es.json`/`messages/en.json`).

## Comportamiento esperado en mobile

- Catálogo de mensajes es/en propio de la app (Flutter tiene su propio mecanismo de i18n —
  `flutter_localizations` + `intl`, o un paquete como `easy_localization`; evaluar cuál seguir
  antes de implementar, no asumir uno sin comparar mantenimiento/comunidad al momento de
  implementar).
- Preferencia de idioma: guardarla localmente (no depende de cookie como la web) — al elegir un
  idioma en la app, persistirlo en el almacenamiento local del dispositivo, y enviarlo como header
  `x-lang` en cada request al backend para que los mensajes de error/validación vuelvan también en
  el idioma correcto.
- Si no hay preferencia guardada: usar el idioma del sistema operativo si es `es`/`en`, si no,
  español por default — mismo criterio de fallback que la web.
- **Nunca hardcodear un string visible en el código** — mismo criterio que
  `TekoApp-Web/.claude/documentation/how-to-contribute.md` sección 3: todo texto visible sale de un
  catálogo de traducciones, en ambos idiomas, desde el primer commit de cada feature (no como una
  tarea de "traducir todo" al final, que es exactamente el tipo de trabajo grande y tedioso que ya
  se tuvo que hacer una vez en `TekoApp-Web` — evitarlo haciéndolo bien desde el principio acá).

## Formato de fecha/hora y zona horaria

Ver `project.md` — nunca usar `America/Asuncion` como identificador de zona horaria (bug real ya
encontrado en backend y en la primera versión del i18n de la web). Usar el offset fijo equivalente
en la librería de fecha/hora que use Flutter (`Etc/GMT+3` si la librería sigue convención IANA
"Etc", o el equivalente de offset fijo que ofrezca el paquete elegido).

## Formato de moneda

`TekoApp-Web` mantiene el formato de moneda (Guaraní, `es-PY`) **fijo independientemente del
idioma de la UI** — es dato de negocio (el negocio es Paraguay-only, no hay conversión de moneda
por idioma), no un detalle de idioma de interfaz. Replicar el mismo criterio: el idioma de la UI
(es/en) no debería cambiar cómo se formatea un monto en guaraníes.
